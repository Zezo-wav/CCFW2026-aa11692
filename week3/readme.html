In Within

For this weeks's assignment, I wanted to create a a triangle that goes into itself, where more triangles appear within the initial triangle and create a cool visual effect, almost like an optical illusion. For the initial sketch, I had some problems with getting the triangles to be positioned properly. I have been struggling with the use of the translate(), scale(), and rotate() functions, where it was hard to program these functions to my desired vision. After the use of the class' LLM and some trial & error, I figured out how to get these functions to work in getting the output I wanted. Using irritation was straightforward and thought provoking, the use of for loops helped me understand what the code was actually doing, therefor it helped in expecting how the code will respond to the instructions. In the end, the results came out great! I love how the piece looks like, especially with the use of HSB color mode, giving a gradual shift in colors with each irrigation of a new triangle.

For the PJ5 polar library, it was a different approach since the polar library has built in functions that directly help the shapes to rotate. Using the initial polar functions (and the help of the class' LLM) I was able to create an interesting look to what my vision looked like. It was kinda funny since the final design of the polar sketch looks pretty different from initial vision, but I still chose to keep it as I thought it look cool. It was somewhat hard trying to translate my vision to the functions of polar since I am much used to traditional coding and the binary nature of coding from the ground up.

I liked both approaches and methods a lot when working within this project. I believe that both approaches have their own benefits and cons. Although for me, I think I had a better time coding natively without using the polar functions. The trial and error that is more prevalent, without the use of polar functions, helps the user to finding new ideas and further enhances their vision. I believe that the nature of polar functions would leave the user with decent results no matter what, which could prevent further analysis and trials. On the other hand, using native code forces the user to really nail down their vision, as the code becomes really binary and is strict to what it can do thus enabling the user to expose themselves to new outputs and ideas. .
